# pychivalry-engine

The engine core of pychivalry: a standalone, dependency-free TypeScript package that turns a
Crusader Kings III mod directory into the game's own diagnostics. Its only source of CK3
vocabulary is the spec package generated by
[pdx-parser-re](https://github.com/Cyborgninja21/pdx-parser-re) from the game executable
(CK3 1.20.0.2, exe sha256 `AE1BA6FF…E81B2D`).

- Parse errors carry the engine's message text from the package's error catalogue.
- Unknown keywords are judged by (name, context) against the engine-derived buckets and the
  package's keyword templates (`has_relation_%s` filled with a scripted relation key);
  iterators against the lists bucket; modifiers against the modifier table plus the
  `%s` templates; retired names get the replacement from the `retired` table.
- Per-keyword scope validity is **not** checked: the package's `scope_validity` is empty
  until an oracle run fills it. The slot and its API (`scopeValidity`) exist.

Zero runtime dependencies; `vscode-languageserver*` is not imported anywhere under `src/`.

## Build, test, CLI

```bash
npm run build          # tsc + copy the spec package into dist/data/
npm test               # unit, golden, corpus and CLI tests (mocha)
npm run lint           # eslint, --max-warnings=0
npm run format:check   # prettier
task engine:build | engine:test | engine:check   # the same from the repository root

pychivalry-engine check <modDir> [--spec <file>] [--json] [--vanilla <dir>]
```

`check` prints the diagnostics of every `.txt` under `<modDir>` grouped by file (or one JSON
object per line with `--json`) and exits 1 when an error is reported, 2 on a usage error.
`--vanilla <game dir>` (the directory holding `common/`, `events/`) indexes the base game's
scripted effects, triggers, lists, modifiers, script values and on_actions so that a mod's
calls into them resolve, and the databases that fill the keyword templates
(`common/scripted_relations`, `common/lifestyles`, `common/dynasty_legacies`). It enables the
undefined-saved-scope check and makes the keyword-template check strict: without a base game
any fill of a template (`has_relation_<anything>`) is accepted, because the vanilla keys are
unknown; with one, the slot must be a key the mod or the base game defines.

## The spec package

`spec.config.json` is the one place that names the package bundled at build time. By default
it points at the vendored copy in `spec/` (`ck3-spec-1.20.0.2.json.gz`, its `.sha256` and the
package's `schema.json`). The JSON is stored gzipped because the repository's pre-commit hook
rejects files over 1 MB; `scripts/copy-spec.js` checks the sha256 of the uncompressed JSON
against the checksum file and writes `dist/data/`. Point `spec` at an uncompressed
`ck3-spec-<version>.json` in a pdx-parser-re checkout to bundle another version.

## Pipeline and checks

`diagnose` runs parse → registry → schema → scope → plug-ins.

**Parse** (catalogue id → when): `expected_between_block_name_and_body` (`key { … }` among
statements), `expected_between_equals_and_arguments` (an operator with no value),
`expected_after_arguments` (a block still open at the end of the file, reported at its
`{`), `unexpected_token_expected_key` (a stray `}` or operator where a statement starts),
`unexpected_token_X_found_at_X_expected` (a key without `=` at top level, `?=` after a
number/date/string; the location is `<file>:<line>`).

**Registry**: `unknown_trigger_X` / `unknown_effect_X` for a key that is not a trigger
(effect) in a trigger (effect) block: made-up names, effects in trigger blocks and the
reverse (names in both buckets are accepted in either), `every_`/`random_`/`ordered_` in
trigger blocks and `any_` in effect blocks, iterators over a base that is neither in the
lists bucket nor a scripted list. A name that fills one of the package's
`keyword_templates` (identity: template and key database; `has_relation_friend`,
`add_diplomacy_lifestyle_xp`) is accepted when its slot is a key of that database in the
workspace or the base game (any fill without `--vanilla`). Workspace (and `--vanilla`)
scripted effects, triggers, lists and values are consulted first. `unknown_modifier_type_X_at_X` in modifier blocks.
Retired names: `PYCH-R001`/`PYCH-R002`. The body of an unknown keyword is not read further.

Where trigger and effect blocks open comes from the package's per-directory schema
(`trigger_block`/`effect_block` fields, `record_body`, `holds: modifiers`), then from
`check/contexts.ts` for positions the schema does not cover.

**Schema**: `unknown_X_in_X` (warning) for a record field the directory schema does not list
(unconfirmed wiki-era fields are allowed); required fields only where the package marks them
(three), reported with the catalogue text the package cites as evidence; a bare value in a
record body; `PYCH-S003` for event content (`namespace = …`) outside `events/`.

**Scope**: chains that start at `root`/`this`/`prev`/`scope:x` are walked link by link
(`failed_to_parse_data_for_event_target_link_link_X_location_X`); `scope:name` without a
`save_scope_as`/`save_temporary_scope_as`/`save_scope_value_as` in the file or the index is
reported as `undefined_event_target_X` (information) when a base game is loaded.

### Package-local message ids

The catalogue has no engine text for these; every other message comes from the catalogue.

| Id | Text |
| --- | --- |
| `PYCH-P001` | Unterminated string starting at '%s' |
| `PYCH-P002` | Malformed inline expression '@[%s]': %s |
| `PYCH-R001` | '%s' was removed in CK3 %s; use %s instead |
| `PYCH-R002` | '%s' was removed in CK3 %s and has no replacement%s |
| `PYCH-S002` | Missing required field '%s' in %s '%s' (fallback; all three required fields of 1.20.0.2 have a catalogue text) |
| `PYCH-S003` | '%s' declares %s content, but %s loads %s content |

## Calibration against vanilla 1.20.0.2

The tables in `check/` are kept as short as the vanilla corpus allows: each entry is needed
for vanilla to check clean. `scripts/vanilla-acceptance.js <game dir>` parses every `.txt`
under `common/`, `events/`, `history/` and runs the checks over the same tree; its record is
`test/acceptance/vanilla-1.20.0.2.json`, and `test/acceptance/vanilla.test.ts` re-runs the
parse when `CK3_VANILLA_DIR` is set.

- `STRUCTURAL` (8): `limit`, `alternative_limit`, `AND`, `OR`, `NOT`, `NOR`, `NAND`, `root`.
  Everything else the review lists as structural (`if`, `else`, `switch`, `random_list`,
  `while`, `hidden_effect`, `custom_tooltip`, `save_scope_as` …) is in a bucket; those whose
  body holds triggers or effects are in `CONTAINERS` (`check/contexts.ts`).
- `ITERATOR_PARAMS` (44): keys the iterators themselves read, scoped to their list bases.
- `MODIFIER_BLOCK_PARAMS` (7): keys of conditional modifier blocks that are not modifiers.

## Porting notes

The AST and position model match the extension's `core/parser.ts`: same `NodeType` values,
same `ASTNode` fields, 0-based line/character, a block's range ending at the start of its
closing brace, list items keeping their text as `value`. Differences a provider may notice:

- New optional `ASTNode` fields: `keyKind`, `keyRange`, `valueKind`, `valueRange`,
  `keyChain`, `valueChain` (scope chains), `keyPrefix` (`scripted_trigger x = { }` keeps
  `key = 'x'`), `expression` (parsed `@[ … ]`).
- `ParseError` gains `code` (catalogue or `PYCH-` id); messages are the catalogue texts, not
  the extension's ("Unclosed brace …" is now "Expected } after arguments").
- `ParsedDocument` gains `bom` and `constants`.
- A date (`1066.1.1`) is a `DATE` token: a dated key or value keeps its text instead of
  becoming the number 1066.1; quoted `"yes"` stays a string (only bare yes/no are booleans).
- Newlines and comments may separate a key, its operator and its value (as in the game's
  reader). Comments between a key and its operator follow the statement as siblings;
  comments between the operator and a block become the block's first children; comments
  between the operator and a scalar value are dropped.
- A block mixing statements and bare values is a `BLOCK` (on_action `events = { delay = …
  event.id }`); `LIST` is a block of bare values only (`rgb { … }` lists carry
  `value = 'rgb'`, `valueKind = 'color'`); `pattern = list "name"` is an `ASSIGNMENT` with
  `valueKind = 'list'`.
- `Symbol` is exported as a type alias of `IndexSymbol`; `SymbolType` gains
  `SCRIPTED_LIST`, `SCRIPTED_MODIFIER`, `MODIFIER_FORMAT`.
- `Workspace` replaces `WorkspaceManager`'s `vscode-languageserver` `WorkspaceFolder` with a
  plain `{ uri, name }` and takes an optional logger instead of the server logger.
- `.eslintrc.json` is the extension's with the naming rule configured for upper-case enum
  members and data-shaped properties, `no-explicit-any`/`no-var`/`no-console` as errors and
  `_`-prefixed unused arguments allowed.
